# 06 · Database (PostgreSQL 18)

> Conventions, ERD index, the full DDL draft, ordering strategy, locking and key queries.
> The DDL is the **design target**. TypeORM migrations implement it as raw SQL ([ADR-016](./11-decisions.md#adr-016), [§9](#9-typeorm-mapping)). Tables marked P2 or later aren't created by the MVP migrations.

---

## 1. Conventions

| Topic | Convention |
|---|---|
| Naming | `snake_case`, plural table names, `<table>_<cols>_idx` / `_uq` / `_fk` / `_ck` |
| Primary keys | `uuid`, **UUIDv7** generated by the application (time-ordered, index friendly, known before insert) |
| Public ids | `short_id text` (8-char base62) for boards and tickets in URLs. Tickets also have a per-board `number` |
| Timestamps | `timestamptz` everywhere. `created_at`, `updated_at` set by the application (no triggers) |
| Archive vs delete | `archived_at` = Trello "closed" (reversible). Delete = hard `DELETE` with FK cascades. `deleted_at` only on `users` / `workspaces` (anonymise / grace period) |
| Enumerations | `text` + `CHECK (col IN (...))` instead of PG enums. Adding a value is a cheap constraint swap, not an `ALTER TYPE` |
| Case-insensitive | `citext` for emails, usernames, slugs |
| Ordering keys | `text COLLATE "C"`, fractional index ([§4](#4-ordering-fractional-indexing)) |
| Optimistic locking | `version int` on aggregate roots: `UPDATE … SET version = version + 1 WHERE id = $1 AND version = $2` |
| JSON | `jsonb` only for snapshots (activity data, event payloads) and UI-only prefs. Never for queryable domain state |
| Ownership | Each bounded context owns its tables. Cross-context access is read-only via ACL readers |

## 4. Ordering (fractional indexing)

Lists, tickets, checklists, checklist items and starred boards are ordered by a **string key** (`position text COLLATE "C"`). The keys come from the `fractional-indexing` algorithm, wrapped in `packages/ordering` so client and server produce identical keys.

| Operation | Example |
|---|---|
| First item in empty list | `keyBetween(null, null)` → `a0` |
| Append after `a0` | `keyBetween('a0', null)` → `a1` |
| Insert between `a0` and `a1` | `keyBetween('a0', 'a1')` → `a0V` |
| Insert at top before `a0` | `keyBetween(null, 'a0')` → `Zz` |

Why this design:

- **One row updated per move.** No renumbering of siblings, unlike integer positions.
- **No precision exhaustion**, unlike Trello's float `pos`. Keys just grow by a character occasionally.
- `COLLATE "C"` is **mandatory**: keys rely on byte order (`'Z' < 'a'`), which linguistic collations don't guarantee.
- **Rebalancing:** if any key in a list exceeds 64 chars (pathological repeated inserts at one spot), a job rewrites that list's keys evenly under the list lock and emits `board.list.rebalanced`. Clients then refetch.

Server rules for `moveTicket` (prev/next resolution, locking): [Activity · Move ticket position](./diagrams/activity/04-move-ticket-position.md).

## 5. Concurrency and locking

| Situation | Mechanism |
|---|---|
| Two users edit the same ticket description | `version` check → `VERSION_CONFLICT` ([Sequence 14](./diagrams/sequence/14-edit-description-conflict.md)) |
| Two users drop tickets into the same gap | `SELECT … FROM lists WHERE id = ANY($ids) ORDER BY id FOR UPDATE` serialises writers per list. The server re-reads real neighbours ([Sequence 12](./diagrams/sequence/12-concurrent-moves.md)) |
| Ticket number allocation | `UPDATE boards SET ticket_seq = ticket_seq + 1 WHERE id = $1 RETURNING ticket_seq` (row lock held to commit, short) |
| Last-admin guard | lock the membership rows of the board/workspace (`FOR UPDATE`) before counting admins |
| Accept invitation twice (double click) | `SELECT … FROM invitations WHERE id = $1 FOR UPDATE` then status check |
| Outbox relay with several workers | `pg_try_advisory_lock(hashtext('outbox-relay'))` → single active relay, preserves order |
| Scheduler jobs on several workers | `FOR UPDATE SKIP LOCKED` batches |

Isolation level: **READ COMMITTED** (default) plus the explicit row locks above.

## 6. Key queries

### 6.1 Board snapshot (cached per board, shared by all viewers)

```sql
-- lists
SELECT id, name, position, wip_limit, version
FROM lists
WHERE board_id = $1 AND archived_at IS NULL
ORDER BY position;

-- tickets with badges (one round trip, grouped aggregates instead of N+1)
SELECT t.id, t.list_id, t.short_id, t.number, t.title, t.position,
       t.start_at, t.due_at, t.due_completed_at,
       t.cover_kind, t.cover_color, t.cover_attachment_id, t.cover_size, t.version,
       (t.description <> '')                     AS has_description,
       coalesce(tl.label_ids,    '{}')           AS label_ids,
       coalesce(ta.assignee_ids, '{}')           AS assignee_ids,
       coalesce(c.comment_count, 0)              AS comment_count,
       coalesce(a.attachment_count, 0)           AS attachment_count,
       coalesce(ci.total, 0)                     AS checklist_total,
       coalesce(ci.done, 0)                      AS checklist_done
FROM tickets t
LEFT JOIN (SELECT ticket_id, array_agg(label_id) label_ids
           FROM ticket_labels GROUP BY ticket_id) tl ON tl.ticket_id = t.id
LEFT JOIN (SELECT ticket_id, array_agg(user_id) assignee_ids
           FROM ticket_assignees GROUP BY ticket_id) ta ON ta.ticket_id = t.id
LEFT JOIN (SELECT ticket_id, count(*) comment_count
           FROM comments WHERE board_id = $1 GROUP BY ticket_id) c ON c.ticket_id = t.id
LEFT JOIN (SELECT ticket_id, count(*) attachment_count
           FROM attachments WHERE board_id = $1 AND status = 'ready' GROUP BY ticket_id) a ON a.ticket_id = t.id
LEFT JOIN (SELECT ticket_id, count(*) total, count(completed_at) done
           FROM checklist_items GROUP BY ticket_id) ci ON ci.ticket_id = t.id
WHERE t.board_id = $1 AND t.archived_at IS NULL
ORDER BY t.list_id, t.position;

-- labels and members are two more small queries
```

The planner pushes `ticket_id` filters into the grouped subqueries via the join. If profiling shows otherwise, switch to `LATERAL` or denormalised counters (`tickets.comment_count`, maintained in the same transaction).

### 6.3 Ticket timeline (comments + activity, keyset pagination)

```sql
SELECT id, 'activity' AS kind, actor_id, type, data, created_at
FROM activities WHERE ticket_id = $1 AND ($2::uuid IS NULL OR id < $2)
UNION ALL
```

## 8. Migrations

- Forward-only. Never edit an applied migration. Fix with a new one.
- Destructive changes follow **expand → migrate → contract** across releases.
- Migrations are TypeORM migration classes in `apps/api/db/migrations/` whose `up()` runs raw SQL through `queryRunner.query()`.
- `migration:generate` is only a starting point. This schema uses features TypeORM doesn't fully model (`NULLS NOT DISTINCT`, triggers, deferred constraints), so review every generated diff by hand.
- Integration tests run all migrations against a real PostgreSQL 18 (Testcontainers) on every CI run.

## 9. TypeORM mapping

Decision: [ADR-016](./11-decisions.md#adr-016).

| Concern | Rule |
|---|---|
| Entities | `*.orm-entity.ts` in `infrastructure/persistence/entities/`. Domain classes have no decorators |
| Mapping | One mapper per aggregate: `toDomain(row)` and `toPersistence(aggregate)`. Repositories return aggregates, never ORM entities |
| Schema | `synchronize: false` everywhere. SQL migrations are the source of truth, and entities only describe columns |
| Relations | No `eager`, lazy relations or `cascade`. Repositories load and save an aggregate's rows explicitly |
| Primary keys | `@PrimaryColumn('uuid')`. Ids come from the application, not `@PrimaryGeneratedColumn` |
| Columns | `citext` and `timestamptz` column types. Position columns set `collation: 'C'` |
| Transactions | `UnitOfWork` wraps `dataSource.transaction()`. The transaction's `EntityManager` is held in `AsyncLocalStorage`, so repositories join it without being passed one |
| Row locks | `setLock('pessimistic_write')`, with `setOnLocked('skip_locked')` for scheduler and outbox batches |
| Optimistic check | Explicit `UPDATE … SET version = version + 1 WHERE id = :id AND version = :v`, then check `affected`. `save()` doesn't compare versions, even with `@VersionColumn` |
| Read models | QueryBuilder or raw SQL, returning plain DTOs |
| Outbox relay | A raw `pg` client, because it needs `LISTEN` and a session advisory lock |
